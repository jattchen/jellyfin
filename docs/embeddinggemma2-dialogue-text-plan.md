## 当前事实与推荐

主 Agent 通过隔离 Jellyfin 的媒体信息、ffprobe 流元数据和同名外挂字幕目录核对，三条所选视频均没有发现可读取字幕。核对覆盖当前媒体源、容器、夹具父目录及符号链接解析后的原文件父目录，不代表其他 NAS 目录不存在字幕。原文件大小和修改时间未变。此前画面里的中文字是烧录字幕，不等同于 SRT 或字幕轨。三条默认音轨序号均为 1、AAC，容器语言标记 `und`；随后用户明确确认主要普通话，首轮采用显式 `zh`，这项语言依据来自用户而非字幕推断。

本机实测 Apple M4、16 GiB。建议首轮独立使用 whisper.cpp `v1.9.5` 的 `large-v3-turbo` 多语言非量化 ggml 模型；仅验证现有 14 个约 12 秒派生短片，总音频约 168 秒。权重官方表约 1.5 GiB，turbo 的本机峰值内存和处理耗时未知，必须在首轮记录；不从别的平台基准外推。

来源：[官方发行 v1.9.5](https://github.com/ggml-org/whisper.cpp/releases/tag/v1.9.5)、[ggml 模型表](https://github.com/ggml-org/whisper.cpp/blob/v1.9.5/models/README.md)、[Apple Silicon 支持](https://github.com/ggml-org/whisper.cpp/blob/v1.9.5/README.md)。框架比较与模型局限见[调研报告](embeddinggemma2-dialogue-transcription-research.md)。

## 已批准的安装位置

whisper.cpp 是运行模型的程序；`large-v3-turbo` 是 Whisper 模型的一种权重，不是再装两个模型。现有 embedding 的源码位于 `~/Documents/projects/embedding-service`，实际运行环境和权重位于 `/Volumes/Turbo/Library/embedding-service/`，权重按 revision 保存在其 `models/` 下；本次已核对运行发布路径和实际模型目录。

沿用代码与运行数据分离的布局，在 `/Volumes/Turbo/Library/transcription-worker/` 保存：

- `releases/whisper.cpp-v1.9.5/`：固定版本的命令行程序及运行所需资源。
- `models/large-v3-turbo/<模型校验值>/`：固定权重及校验清单，独立于程序版本。
- `runs/jellyfin-pilot-<日期>/`：首轮的临时输入、原始转写、日志和验收证据，临时文件与应保留结果分开。

项目目录只保存源码、构建/调用脚本和下载来源/校验清单，不提交模型、运行缓存或验收音频。插件使用配置指定完整程序与模型路径，未来其他项目可以复用同一权重，不必各下载一份。本次不移动现有 embedding 的任何文件，也不把转写安装进 embedding 的运行环境；没有新增后台服务或自启项。Turbo 不可用时报告不可用，不在系统盘静默建另一份。

这是针对本机已有 Turbo 布局的建议；macOS 一般将持久应用支持数据放在用户 `Library/Application Support`、可重建缓存放在 `Library/Caches`，而不是开发源码树。[Apple 文件目录说明](https://developer.apple.com/library/archive/documentation/FileManagement/Conceptual/FileSystemProgrammingGuide/FileSystemOverview/FileSystemOverview.html)。模型版本作为部署依赖独立管理，缓存与重要索引/结果分别保留，不把源码 worktree 的存续当作模型存续条件。

## 用户会怎样搜索

长期目标仍是同一个 Jellyfin 搜索框、原标题搜索保留、点击从命中时间连续播放。对白有文字依据后，建议分别呈现画面候选和对白文字候选，避免未经验证地合并成一个总榜。对白候选附可读摘录及来源：已有字幕或自动转写。自动转写标为未经人工核对，不说成已证明的原话。此界面方案尚未实施。

按意思查询继续用现有 EmbeddingGemma 2：查询 `task=query`，字幕或转写内容 `task=document`。相似度只负责召回，不证明语句确实出现，也不自动解决无答案判断。确切词句查找可读取保存的文字做匹配，但匹配到自动转写文本也不等于音频事实。首版不另加生成式回答、说话人身份推断或新的重排模型。

既有 SQLite 可保存文字及向量，不要求 Qdrant。若后续采用 SQLite FTS5，中文检索方式必须单独核验；例如 trigram 的全文匹配不支持少于三个字符的查询，不能漏掉“西线”这类两字词，也不能把整句中文默认交给英文分词。[SQLite FTS5 官方限制](https://www.sqlite.org/fts5.html#the_trigram_tokenizer)。本轮不实现全文检索。

## 能力与数据边界

- 有真实文本字幕时，优先在 Jellyfin 宿主适配层按当前媒体源及字幕轨读取。官方 `v12.2` 的公共 `ISubtitleEncoder.GetSubtitles` 可以返回 JSON，并有起止 ticks 和保留原时间戳参数；JSON 的 `TrackEvents` 包含文字及起止 ticks。读取前后仍由插件检查当前用户、影片、媒体源和版本，不把内部接口当权限检查。不会下载网上字幕、上传或改写源文件旁的字幕。
- 当前三条无可读字幕，因此首轮只评估转写。worker 是独立 CLI 与固定模型文件，不往插件 DLL 内放 Python、模型或 GPU 原生绑定；安装目录与系统 PATH 分开，不设置新开机服务、不占新端口。
- 从派生样本的默认音轨取 16 kHz、单声道、16-bit PCM WAV，检查音轨、时长和起点，临时文件放私有验收目录；原片及现有媒体库只读。
- 输出保留未经修改的转写文字、段级起止、来源、语言参数、检测结果、whisper.cpp 构建/版本、模型校验值、解码参数、音频身份和任务状态。未知值保持未知。未确认来源或时间不能假装完成。
- 文本记录和向量与联合窗口分开签名、分开有效代次和质量策略。模型签名一致不代表不同表示可以混用；不能写入现有联合窗口表或沿用未校准的 `0.35`。试验全部使用私有文件或独立实验数据库，正式表不迁移。
- 当前 `ActiveSignature()`、`BeginRebuild()` 和恢复判断绑定全局联合索引；当前 `EmbedTextAsync()` 硬编码 `task=query`。未来接入需显式支持 `document`，区分共享模型签名与各表示的处理/来源版本、代次和质量策略，避免文本重建或不兼容停掉联合检索。这是另行实施的工作，不是 A 的前置开发；B 私有验证可以直接按现有模型协议发送 `document`，不调用旧查询包装器。
- 后续产品接入时复用现有权限、内容版本、取消等待及共享 embedding 派发器；后台转写进程由插件拥有，一个后台模型任务运行，播放/手动暂停停止新增任务。杀停转写须确认对应子进程退出后再删除输入或释放占位，未知状态不能假装停止。这里没有承诺外部客户端与本插件的 GPU 使用自动隔离。
- 独立 worker 升级不要求改 Jellyfin 核心代码；未来宿主仍按实际版本单独验收。文本 schema 升级只涉及插件数据库，先备份、保留原联合数据，旧插件不写新 schema。试验阶段不触碰这项迁移。

接口依据：[v12.2 ISubtitleEncoder](https://github.com/jellyfin/jellyfin/blob/v12.2/MediaBrowser.Controller/MediaEncoding/ISubtitleEncoder.cs)、[字幕 JSON 输出](https://github.com/jellyfin/jellyfin/blob/v12.2/MediaBrowser.MediaEncoding/Subtitles/JsonWriter.cs)。

## 时间怎样映射

转写时间属于输入 WAV 内的估计；原片时间为 `派生样本原片起点 + 音频内偏移`，再乘每秒 1000 万 ticks。保留采样时间原点和音视频差异，不能把未知偏移当 0。映射不使估计变成真实字幕时间，也不证明逐词对齐。

候选须完整包含冻结意思。短于 5 秒的完整语句可以扩充播放上下文到 5–10 秒，仍保存真实估计边界；需要超过 10 秒才表达完整意思时标为本轮定位不通过，不能把标签裁短。词级/DTW 时间和 WhisperX 不属于首轮；当前段级时间是否足够必须实测。播放器起点误差与语义区间长度分开检查。

声音候选边界只来自实际 ASR 段边界或相邻段合并。标点可用于文字分句，但不能根据标点、字数或冻结目标时间推算/修剪新的声音边界。文字覆盖与时间定位分别记录：若文字完整但只有 12 秒整体可确认，就记“文字可用、定位未通过”；旧听辨不能覆盖新的边界时记未知，不据此否定所有转写方案。

## 两阶段验证与预算

下列为验证边界。用户已批准阶段 A 的安装、一个模型下载及原 14 个短片的转写；阶段 B 仍须另行确认，不能因为 A 通过就自行扩大到整个库。

### A：先核对转写内容和时间

1. 工具与权重固定为 whisper.cpp `v1.9.5`、非量化 `large-v3-turbo`，记录官方模型校验、实际文件 SHA256、构建选项和实际 Metal 日志。只装入任务专用工具目录，不替换现有服务或插件，不安装另一套 Python ASR。
2. 14 个完整派生样本各转写一次，最多 14 次 ASR，输入总约 168 秒。不对 42 个重叠窗口重复转写，不读整片音频，不追加静音/其他素材推理，不自动跑 `large-v3` 或其他框架。
3. 用户已确认主要普通话，首轮显式固定 `--language zh`，不沿用默认 `en`。仍记录实际配置和异常；发现与确认语言不一致的素材时停止新增派发、保留证据，不静默改语种重跑。
4. 保存全部原始结果和失败，不人工改字后再计成绩。沿用五条冻结对白的含义与原片目标；用先前听辨回执和烧录字幕核对，声音边界不能确认时保留未知，必要时在用户可操作的浏览器给出短片供核对。转写不凭音色或画面补入“男子/女子/老人”等没有说出的身份，不要求转写文字逐字复现查询中的旁述标签；检索查询本身仍保持原文。
5. 事前门槛：分别记录五条对白的完整含义文字覆盖和区间定位，至少四条同时具备完整文字依据、有效映射和有内容证据支持的 5–10 秒区间，才考虑阶段 B；这是有限试验的继续条件，不是 ASR 总体准确率。位置与播放器起点另测。文字来源不明、幻觉或未确认不能当通过。一条失败不代表所有 ASR 无效，但低于 4/5 停在有限验证。
6. 无语音样本若在现有 14 条中实际得到听辨确认，单列误出字；不能凭黑画面判断静音。两条无答案是查询案例，并不等于两段静音音频。没有静音对照证据就不报告“静音幻觉已通过”。
7. 记录下载、峰值内存、准备/转写/等待时间及取消恢复。不把单轮时间直接换算整库性能。技术失败保留检查点，已成功的样本不重复派发；不以零文字或空时间冒充完成。

A 不生成新的文本向量、不调用 embedding-service、不改网页或原索引。用户于 2026-10-15 确认安装布局后回复“同意，请继续”，授权本阶段的私有工具安装、一个 ASR 模型下载及上述 14 次转写预算。

### B：文字检索验证（已另行批准并完成有限诊断）

仅在 A 的文字/时间质量通过后考虑。继续同一 14 条派生样本及七条冻结查询，不改变原画面检索或正式实例。

- 复用已有七条 `query` 向量，先核验模型、revision、processing_id、维度一致；不兼容时停止，而非静默重算新查询。
- 分句/相邻上下文合并规则在看排名前固定，依据时间和标点，不按某条查询挑选文本。完整原始 ASR 输出保留；单个检索单元保留文字与估计时间，不为了 5–10 秒裁掉半句。
- 最多 56 个新的 `document` 文本嵌入（每短片最多四个检索单元，作为预算上限）。若规则要求更多，停止并单列，不能悄悄截断后声称覆盖完成。不在这个上限内加入新校准查询或其他表示。
- 先单独比较五条对白和两个无答案的文本排名及真实内容；对白目标前三至少 4/5。默认可见结果能明确拒绝无答案仍是最终产品门槛，但本阶段的既定预算没有独立校准，不能保证完成这一项，也不能拿总会存在的最高相似项当答案。
- 不用同七条验收查询挑阈值、权重或不断改提示。文本默认可见门槛需独立校准，原视觉校准不代表对白文字质量；独立校准集的具体数量与推理预算须另行确定。若无已验证的拒绝策略，本轮分别报告“对白完整含义 Top3 成绩”与“负例拒绝未完成”，即使对白达到 4/5，也不能宣布负例或完整功能通过；不通过隐藏所有结果或沿用 `.35` 伪造通过。
- 本轮不会把 B 的候选直接上线，也不实施新 API、数据库迁移或 UI。产品接入与完整三条视频验收必须在这项有限验证后再决定。
