# 对白文字依据：本地转写方案

状态：2026-10-15 的方案比较。没有安装程序，没有下载权重，没有调用转写，也没有读取或解码视频。转写能力来自官方说明，还不是这台 Mac 上的转写结果。

画面索引、现有 EmbeddingGemma 2 服务和已经做过的三次试验保持原样。联合表示的原成绩是画面前三 5/5、对白前三 3/5、负例 0/2。纯音频对白确认 2/5。固定 RRF 对白确认 2/5。三组数字各自保留，不能连写成同一次试验的 5/5、3/5、0/2。

下面的字幕和音轨事实由主 Agent 测得。本文件作者这一轮没有转写，也没有另行读取媒体元数据。主 Agent 的测量是：Jellyfin 条目均为 HTTP 200，每个 MediaSource 的字幕轨为空；ffprobe 只有视频和音频，第二条另有一条 MJPEG 封面流，类型仍是视频，不是字幕。夹具父目录，以及每个符号链接解析后的原文件父目录，按同名、语言和标记匹配字幕扩展名，结果都是 0。三个原文件事实在核对前后未变。这只说明这三条在上述位置没有可读字幕，不说明 NAS 其他目录没有字幕。主 Agent 此前见过烧录在画面上的中文字；那些字仍然不是可读取的字幕轨。中文烧录字幕不能用来认定口语音种。三条默认音轨的语言标记都是 `und`，用户听辨没有明确确认语种。因此这一轮没有字幕轨可调用，对白文字若要有时间，只能来自转写估计。

本机 PATH 里没有 `whisper-cli`、`whisper` 或 `whisperx`。系统 Python 3.9 没有 `mlx_whisper`、`faster_whisper` 或 `whisper` 模块。没有遍历其他虚拟环境，所以不能说这台机器上完全没有转写程序。

## 首选

用独立的本地 worker 调用 [whisper.cpp](https://github.com/ggml-org/whisper.cpp) 命令行，在 Apple Silicon 上走它文档所述的 Metal GPU。模型先用官方 ggml 的 `large-v3-turbo`。Jellyfin 插件只负责排队、取消、记录版本和把时间映射回原片，不携带 Python，也不携带模型权重。

词级时间不是首轮强制。段级起止时间只是初始候选，要实测它是否包含完整意思，以及能否落到大约 5–10 秒。测不到就保持未通过，不能把标签改短来伪装通过。官方命令行默认输出片段起止时间；把片段切成单词被仓库标成实验功能。

首轮模型固定为 `large-v3-turbo`。失败后把成功和失败记录交回决策，不自动改跑 `large-v3` 或其他模型。mlx-whisper 是 Apple Silicon 上的备用实现。faster-whisper 的官方 GPU 路径是 NVIDIA CUDA，不作为这台 Mac 的首选。

## 为什么是这一条

[whisper.cpp 说明](https://github.com/ggml-org/whisper.cpp/blob/master/README.md) 写明：Apple Silicon 上推理完全走 Metal GPU，并提供命令行 `whisper-cli`。模型用 ggml 文件，不依赖 Python 运行时。[模型表](https://github.com/ggml-org/whisper.cpp/blob/master/models/README.md) 给出磁盘占用：`large-v3` 为 2.9 GiB，`large-v3-turbo` 为 1.5 GiB。[顶层 README 的内存表](https://github.com/ggml-org/whisper.cpp/blob/master/README.md#memory-usage) 只有一行 “large”：磁盘 2.9 GiB、内存约 3.9 GB。turbo 没有单独的内存数字，因此 turbo 在本机的运行内存是未知，不能用 3.9 GB 代替。

[OpenAI 模型卡](https://github.com/openai/whisper/blob/main/model-card.md) 和 [Hugging Face 上的 large-v3-turbo 说明](https://huggingface.co/openai/whisper-large-v3-turbo) 一致：turbo 是把 large-v3 的解码层从 32 层减到 4 层后再微调，参数量 809M，多语言，速度更快，质量有小幅下降。OpenAI 说明还写明 turbo 不用于把外语翻译成英语；本方案只做原语言转写，不做翻译。

[mlx-examples 的 Whisper 说明](https://github.com/ml-explore/mlx-examples/blob/main/whisper/README.md) 是 Apple 的 MLX 实现，安装 `mlx-whisper` 后用 Python 命令行或函数调用，可从 Hugging Face 拉 MLX 格式模型，也支持 `word_timestamps=True`。它没有给出 large-v3 或 turbo 的官方下载体积和运行内存，这两项记为未知。它把 Python 和权重管理放在一起，插件边界比 whisper.cpp 更难隔离。

[faster-whisper 说明](https://github.com/SYSTRAN/faster-whisper/blob/master/README.md) 的 GPU 要求是 CUDA 12 的 cuBLAS 和 cuDNN 9。示例设备是 `cuda`。CPU 示例存在，基准机器是 Intel Core i7-12700K；GPU 基准是 NVIDIA RTX 3070 Ti。[CTranslate2 预编译包的硬件页](https://opennmt.net/CTranslate2/hardware_support.html) 把 GPU 列为 NVIDIA，CPU 包括 AArch64。因此在这台 Mac 上，官方预编译路径能确认的是 CPU，不能把 NVIDIA 或 Intel 的耗时当成 M4 的耗时。运行内存没有针对 Apple M4、16 GiB 的官方数字，记为未知。

WhisperX 不列入首轮。faster-whisper 的说明把它描述成用 wav2vec2 做更细的词级时间。段级时间若不满足完整意思或 5–10 秒定位，首轮停在实测结果，不自动换对齐框架，也不改短时间标签。

## 语言、幻觉和时间

三条默认音轨的语言标记都是 `und`。烧录字幕呈中文，但此前用户听辨没有明确确认口语音种。因此普通话、中文口语都还不是现场已验证的事实。中文查询和画面上的中文，也不能代替这次确认。

语言是显式选项，不把“必须中文”或“首轮固定 zh”写成已定事实。[whisper.cpp 命令行说明](https://github.com/ggml-org/whisper.cpp/blob/master/examples/cli/README.md) 里 `--language` 的默认值是 `en`，未知时不能沿用这个默认。音轨仍是 `und`、用户尚未确认实际语言时，用 `auto` 做发现，并保留检测结果。只有用户确认实际音轨语言之后，才能改为 `zh`。中文烧录字幕、中文查询都不能代替这次确认。

[OpenAI 模型卡](https://github.com/openai/whisper/blob/main/model-card.md) 写明：弱监督训练会写出音频里并没有说过的文字，也就是幻觉；语言之间的准确度不均匀，训练数据少的语言更容易重复和幻觉。模型卡没有给出中文人名、背景音乐或这条片子的错误率。人名没有准确性保证。静音段也可能被写成文字。同一命令行有 `--no-speech-thold`，默认 0.60，用于判断无语音。它降低无语音段出字的机会，但不证明剩下的字就是原话。

片段时间是默认输出，形如起止时刻加一句文字。它只是初始候选。要实测该段是否包含完整意思，以及映射回原片后是否满足大约 5–10 秒的定位。不能因为命令行给出了起止时间，就默认这两项已经满足。`--max-len 1` 被标成实验性的词级时间；`--dtw` 是另一条 token 级时间。词级不是首轮强制。逐字时间不当真。段级结果不满足时，不能改用更短的标签伪装通过。完整意思的核对用已有的用户听辨和烧录字幕；这两样核对意思是否完整，不证明逐字为真，也不证明口语音种已经确认。

时间的真实边界是：whisper.cpp 的起止时刻属于送进命令行的那段音频，不是 Jellyfin 的 ticks，也不是原片时间。14 个短片各自有已知的原片起点。映射是“短片起点 + 转写片段在该音频内的偏移”。偏移来自模型，映射只做加法，不会让估计变成字幕时间轴。

官方 v12.2 的 `GetSubtitles` 可以带媒体源、字幕流序号、起止 ticks，并保留原始时间戳。那是以后宿主适配层读取文本字幕的接口。这一轮三条都没有字幕流，所以不能用它取得对白时间。烧录字幕没有流序号，同样不能走这个接口。

## 文字从哪来，能相信到什么程度

| 来源 | 可以当作什么 | 不能当作什么 |
| --- | --- | --- |
| 这三条当前可读的文本字幕 | 没有发现，因此不能作为这一轮的对白文字 | 核对范围只包括当前媒体源、容器内流，以及夹具目录和原文件父目录的同名边车 |
| 烧录在画面上的字 | 主 Agent 过去见过，它只属于画面 | 不是可读取的 SRT，这一轮也没有字幕流可抽取；转写不负责把它抄下来 |
| 本地转写 | 一段可能相关的文字，带估计的起止时间 | 不是“片中确实说过”。无可靠片段时，对白结果应是非命中 |

语义检索只比较这段文字和查询的意思。它不核对用词是否与台词一致，也不保证无答案查询会被拒绝。转写完成之后，不保证对白验收达标，不保证人名准确，也不保证命中落在 5–10 秒内。

## 插件和 worker 怎么分开

worker 是本机一个单独程序，建议就是固定版本的 `whisper-cli` 加上它读取的 ggml 文件。插件通过本地任务调用它。

- 取消：只结束本任务拥有的对应 worker 进程，确认退出后再清理该次临时音频和释放占位。已完成并写入检查点的片段保留，未知退出状态不当作已停止。
- 断点：每条派生样本用原片身份、样本起止、默认音轨编号、模型文件校验值和 worker 版本做键。完成后跳过，不重复转写。
- 版本：记录 whisper.cpp 的构建标识、ggml 模型在官方表中的 SHA，以及实际使用的 `--language`。换任何一项都是新版本，不覆盖旧结果。
- 原文件只读：只从视频读取，抽出默认音轨。临时 wav 放在验收目录，不写回影片、不改 Jellyfin 媒体库。
- 音轨：三条现场媒体源的默认音轨序号都是 1，对应 AAC，语言标记都是 `und`。`und` 只表示容器没有填写语种，不是已经听辨过的普通话或中文。不要把第二条的 MJPEG 封面当成音轨或字幕。不在这次试验里改选其他音轨。
- 升级隔离：worker 和权重放在插件目录之外。升级官方 Jellyfin 或替换插件，不删除、不替换这份 worker。

官方顶层说明仍建议用 ffmpeg 把输入转成 16 kHz、单声道、16-bit WAV。命令行帮助则列出 flac、mp3、ogg、wav。为避免两种说法不一致，worker 统一喂 WAV。源视频本身保持只读。

现有 embedding 服务不修改，也不在转写进程里加载第二套 EmbeddingGemma。转写得到的文字若要检索，仍调用现有的文字嵌入接口，但必须使用 `task=document`，并使用独立签名。不能沿用联合窗口的 0.35 门槛。

当前插件只有联合窗口一种表示、一个全局签名，以及相关下限 0.35。转写文字的向量不能写入这张表。它需要单独的来源、模型版本、时间质量和文本检索规则。不把联合排名和音频排名再混在一起刷分。接入方式、两阶段预算和有限验证范围由主 Agent 决定；本文只规定转写首选和时间边界。

## 有限验收

首轮只转已经冻结的 14 个完整 12 秒派生短片，合计 168 秒，每段一次。不对 42 个重叠窗口做转写，也不扩到合计约 68 分钟的原片。

主 Agent 另行制定两阶段预算：先看转写文字和时间质量，通过之后才做文本语义召回。原有 7 条文字查询向量可以复用，不为了这一路重嵌查询。新的文档向量只给保留下来的转写片段，次数等于实际留下的片段数，任务类型必须是 `task=document`，签名独立。某段没有留下文字，则该段新增 0 次。片段数要等转写之后才知道，不能事先写成 42。

每个转写片段的起止是该 12 秒音频内部的估计，逐字时间不当真。加上这条派生样本在原片中的起点，才得到原片时间。不能把这个和写成 Jellyfin 字幕 ticks，也不能把它写成必落在 5–10 秒内。检索仍可同时使用已有画面索引。意思是否完整，用已有的用户听辨和烧录字幕核对。

不根据这 7 条查询改门槛、改目标、混排名或手工改正转写后再算通过率。语义文本不保证无答案被拒绝。一次试验的结果，无论好坏，都另存，不改写联合、纯音频和 RRF 的原成绩。

## 可验证的失败和退出

一条样本失败，不把整条转写路线判成无效。事先的文字和时间质量闸要达到至少 4/5，并且没有把没说过的内容写成原话，才进入后面的文本语义召回。未达到这个闸，就停在当前结果，把成功和失败都留下。

技术异常只停止当前这一轮：worker 不能在本机以 Metal 启动，官方 ggml 的 `large-v3-turbo` 无法被该构建加载，或者原片被要求写入。已完成的片段和失败记录都保留。不自动改跑 `large-v3`、mlx、faster-whisper 或 WhisperX。

发现阶段使用 `auto` 并保留检测结果。未确认口语音种时改指定 `zh`，算偏离本边界，不拿来补救成绩。静音段仍写出成句文字时，记为质量问题，不调门槛、不混排名。无答案能否被语义文本拒绝，留到第二阶段观察，不事先保证。源文件必须仍是只读。

## 主 Agent 直接裁决的技术项

worker 用 whisper.cpp 而不是 mlx 或 faster-whisper；首轮模型固定 turbo；输出用带时间的 JSON 或 SRT，但逐字时间不当真；临时音频为 16 kHz 单声道 WAV；词级对齐和 WhisperX 不进入首轮；权重与二进制放在插件目录外。语言不是已经问完的结论：未知时用 `auto` 并保留检测结果，用户确认实际音轨语言之后才能指定 `zh`。两阶段预算、文本门槛和是否把新向量接入搜索，由主 Agent 制定，不沿用 0.35。失败后返回决策，不在本文件里安排自动换模型。

本文件仍只是方案，不是实施许可。
