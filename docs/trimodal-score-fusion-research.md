# 画面、声音、转写文字三路评分：算法调研

2026-10-15。范围仅为算法、现有接口与已有证据核对；没有新增推理、安装、媒体解码、索引或产品修改。原 24 题单文字校准方案没有执行，三路方案也没有因此自动获得试验授权。

## 本轮裁决

更合适的方向是**分别召回、对齐候选、学习或校准融合、单独检验无答案拒绝**。不是寻找一个无需标注、只把三路数字套进去就能可靠理解所有查询的公式。

**当前主推荐：无答案背景校准后的最大证据融合，不加共识奖励；再单独对整次检索做拒绝校准。** 这比先前“max＋少量加分”更容易控制并解释重复信号与误报，但没有本机三路成绩，不能宣称排名已经提高。

有足够新标注后，再考虑带少量非线性特征的 L2 正则化逻辑回归/轻量排序器；它只学习少量评分参数，不需要新下载一个大语言模型。普通描述与明确的多条件查询需分开验证。主 Agent 已核对既有调研与顾问的证据及公式，所有新公式均未在本机三路向量上训练或验收。

## 推荐算法如何组成

对每一路 `m`，用真实无关匹配拟合背景分布。将余弦 `s_m` 映射成高分尾部频率 `p_m`，含义为“无关候选里取得至少这么高分有多常见”，再计算：

```
E_m = -log(p_m)
F(candidate) = max(E_visual, E_audio, E_text)
```

经验尾部估计需平滑，不能让少量样本中未见更高分就产生 `p=0`、无穷证据。`p_m` 是背景频率估计，不是“不相关概率”，`1-p_m` 也不是相关概率；本项目尚无可靠的逐路尾部拟合数据。它作为固定变换后，最终检索级校准的有效性不要求每一路都已具有独立、精确 p 值的保证，但不能据此编造各路自身的统计保证。

相比原始 max，变换能把“某路普遍偏高”与“某路高分很罕见”放到可比较的背景证据尺度。相比三路相加，max 不会因声音和派生文字同时高分就再给一次共识奖励；它仍会随通道数量增加而更容易挑到偶然高分，所以不能省略后面的整次检索校准。

候选生成、时间关联、融合与去重固定后，对每条独立无答案查询记录全库最高 `F`，形成后文 `p_null` 的参考。其目标是控制“无答案查询仍返回至少一条明显相关结果”，不是保证有答案时 Top3 的每条都正确。低尾部频率也可能只是离群错误，最终仍须在正例中检验正确召回与定位。

## 已知事实及不能跨越的边界

- 旧联合音视频：画面 5/5、对白 3/5。旧纯音频与“联合＋纯音频 RRF”各确认对白 2/5；这些不是纯画面＋纯音频＋ASR 文字三路试验。
- Qwen 转写与已知目标时间听辨 5/5。之后 25 条文字候选、七条冻结查询的完整对白 Top3 为 4/5，D1 第 4，其余第 1。见[阶段 B](qwen3-text-retrieval-pilot.md)。七题已经看过，不能再用来选择算法、拟合权重或门槛后声称是未见验收。
- 原音视频为 42 个固定窗口，文字为 25 条另一套时间边界。不能把两种排名按“同一部片子”直接合起来；需要每个候选明确媒体源、内容版本和实际时间范围。
- 当前 embedding-service 每个输入返回一条归一化 768 维向量；视频可关闭音轨，声音可单独输入，文字显式 `task=document`。这允许三路分开，但没有逐词/逐帧多向量输出。
- Google 官方说明跨模态在共享向量空间比较；这不等于已经验证每一路的同一个余弦下限具有相同误报率。[EmbeddingGemma 2 官方多模态说明](https://ai.google.dev/gemma/docs/embeddinggemma/multimodal-embeddinggemma-with-sentence-transformers)
- 模态间隙研究表明共享空间中可能存在模态分布差异，但其研究对象含 CLIP 等模型，不能据此断言本项目 EmbeddingGemma 2 的三路分布已经测出差异。旧 joint 和 text 还同时改变了分段，无法隔离这一因素。[Mind the Gap](https://arxiv.org/abs/2203.02053)

## 先区分三个问题

1. **召回**：每路各自找候选，合并候选集合，不能由任一路提前淘汰其它路的强匹配。
2. **排序**：对同一时间候选，组合多路证据决定次序。
3. **拒绝**：某条查询在整个当前可搜索范围中都没有足够证据时，能否不把最高名次当作答案。排序优异也不自动解决拒绝。

时间归并必须在评分前定义。文字保持自然句及其时间，不能为了固定网格截断含义，也不能把一句的高分无条件复制到所有相交窗口。可把完整句区间作为候选、补算该区间的音画表示，或保留各自候选及证据范围；两条路线均需预注册，不能按已知目标时间修剪。无声音或无转写是缺失，不是余弦分数为零；不能通过补零或随意补最差名次改变语义。

## 候选算法及判断

| 方法 | 适合做什么 | 本项目中的主要问题 | 处置 |
| --- | --- | --- | --- |
| 三路原始余弦平均/手工权重和 | 快速排序基线 | 单路强匹配可能被其它路压低；权重没有证据；尺度未校准 | 不作为最终默认 |
| 校准后取最大值 | “任意一路强匹配即可”的普通描述 | 会挑中某一路的偶然高分；不能保证复合条件都成立 | 保留为明确基线，必须校准最终误报 |
| 校准后的凸组合（CC） | 低参数、保留分差、可学习少量权重 | 仍可能压低单路真匹配；声音与其转写会重复贡献；不同查询可能偏好不同权重 | 值得小范围对照，不先拍定权重 |
| RRF | 缺乏可比尺度时的排序基线 | 丢掉强弱分差，相关音轨/转写会重复贡献，分数不能直接用于无答案门槛 | 仅作排序对照 |
| L2 逻辑回归/轻量排序学习 | 从正确/错误样本学各路贡献与重复信号 | 需要足够新标签、分组留出；最简单三路线性和表达能力仍有限 | 有数据后的主方向，保留 max 等特征 |
| 查询自适应权重/混合专家 | 不同查询分别偏重画面、声音或对白 | 必须有可靠查询特征及训练数据，不能从七题直接学门控 | 后续路线，不先加神经门控 |
| noisy-OR / 独立似然相乘 | 在适当概率与独立性假设下合证据 | 余弦不是概率；声音与 ASR 不独立，易夸大置信度 | 当前不采用 |
| ColBERT 类 token late interaction | 细粒度词级匹配 | 需要 token 多向量；当前 API 仅有池化单向量，不是换合分公式即可使用 | 不属于当前接口内算法替换 |

加权余弦和与 max 数学上不要求输入是概率，也不默认通道独立；限制是其相关性尺度和验收依据尚未建立。不能把 noisy-OR 的独立性要求移植成这些算法的必要条件。

CC 与 RRF 的一手比较支持“保留分差的低参数融合值得测”，但原论文是词法＋语义检索，不是本项目三路模型，不能套用其胜负结论。[Bruch 等：An Analysis of Fusion Functions for Hybrid Retrieval](https://arxiv.org/abs/2210.11934)

RRF 公式为 `sum_m w_m/(k+rank_m)`。`k` 会改变靠前与靠后名次的相对影响，不只是统一缩放；缺失候选通常不贡献该路分数，不能随手补 `N+1` 还声称是原算法。官方文档明确建议不要用 RRF 的 `min_score` 过滤相关性或跨查询比较其分数。[OpenSearch RRF 规范](https://docs.opensearch.org/latest/vector-search/ai-search/hybrid-search/rrf/)

`min_m 1/(60+rank_m)` 等于 `1/(60+max_m rank_m)`，只是按最差名次排序；常数 60 在这条新公式里不改变次序。这不是 RRF 求和，也没有由 RRF 论文获得子条件合取的有效性保证。

## 为什么学习融合也必须保留“单路强匹配”

候选特征可以从很少的数开始：

```
x = [画面分, 声音分, 文字分, 三路最高分, 缺失标记]
融合分 = b + w · x
```

各路变换或标准化参数只从训练部分估计，不能每个查询把第一名拉到 1。特征和正则化强度在看最终验证前固定。声音与 ASR 相关，不做两次“独立概率”相乘；同时，普通逻辑回归不假设输入特征彼此独立，但也不保证能凭少量数据自动彻底消除重复计数。可另对照预先固定的音轨/转写分组，不能看分数后逐题挑组。

为什么不只放三个分数：纯算术例子（不是实测）中，单画面强匹配 `(0.9,0.1,0.1)` 平均仅 `0.367`，三路一般的 `(0.55,0.55,0.55)` 平均为 `0.55`。若三种单路强匹配都应被接受、三路一般的候选应拒绝，简单非负加权和也不能同时满足：三个单路的得分平均仍低于该中等候选。增加 `max` 特征可以表达这种 OR 型偏好，但不能解决“某一路错误地打了高分”的根本信息不足。

逻辑回归可用 sigmoid 输出 0–1 的估计值；落在 0–1 不证明概率准确，更不能默认以 0.5 为产品门槛。训练、概率校准和最终验证必须有分离的数据或严格的分组交叉验证。[逻辑回归及正则化](https://scikit-learn.org/stable/modules/linear_model.html#logistic-regression)、[概率校准](https://scikit-learn.org/stable/modules/calibration.html)

## 多条件查询需另有条件分数

普通查询可以允许任一路支撑。对于“红衣人在雨中说去西线”，仅有整句的三个总分不能证明衣服颜色、雨景和对白均成立。

若要支持明确合取，先获得明确子条件及各自证据：画面条件、声音条件、对白条件分别匹配，在同一时间候选上检验。此时可对必需条件设置各自门槛，或将经校准后的最低条件分作为排序因素；不是直接把三路全句分数取 min。如何拆条件、选适用通道本身需要额外能力或明确的用户输入，不假称现有一个查询向量已经提供它。

视频搜索中的查询相关权重有直接研究依据，但同样依赖查询语义特征和训练查询，并非无需数据的公式。[IBM：Dynamic Multimodal Fusion in Video Search](https://research.ibm.com/publications/dynamic-multimodal-fusion-in-video-search)

ColBERT 保留 query/document token 的细粒度表示后做交互；不能把它的 MaxSim 当作“三路整段分数取 max”的理论保证。[ColBERT 原论文](https://arxiv.org/abs/2004.12832)

## 拒绝无答案：对融合后的整个搜索做独立校准

每条已确认无答案查询，都在固定的完整候选库上运行相同融合流程，记录它的最高融合分。锁定算法与候选库之后，用独立的负例查询观察这些“偶然最好结果”的分布，再确定允许多少误报，而不是只比较某一个片段的余弦。

一种统计候选是 split-conformal/null-score 校准。对固定评分算法，设独立负例查询的全库最高分为 `Z1..Zn`，新查询最高分为 `Z`，可考察：

```
p_null = (1 + count(Zi >= Z)) / (n + 1)
```

很小的 `p_null` 表示该最高分不像这批无答案查询；它不是“命中正确的概率”，也不保证被选中的具体片段正确。若查询样本与将来请求可交换、算法与候选库已固定，可借鉴 conformal 检验的边际性质；不能自动对任意语种、任意新片库或挑选过的难例声称严格误报控制。[Testing for Outliers with Conformal p-values](https://arxiv.org/abs/2104.08279)

这一路适合研究拒绝层，不替代三路排序。库变大、时间窗变密、查询类型或融合规则改变，都可能改变最高分的背景分布，需重新核验。175 个 query-document 分数不是 175 个独立查询，更不是独立的无答案最高分样本。

样本量边界也必须如实保留：8 条负例的最小经验 conformal p 值为 `1/9`，不能支撑 5% 级别的这种检验分辨率；19 条只能让最低刻度达到 5%，不等于已经稳定估计所有条件误报率。另按独立同分布二项模型计算，8 条负例零错误的单侧 95% 上界仍约 31.2%。这两种数字是不同口径，均不是本机质量成绩。

不把“减去无关背景均值”叫似然比：均值差不描述尾部，也没有完整的相关/无关密度估计。真正的似然比需要估计联合分布或有明确建模假设，当前小样本不适合装成精确概率。

## 后续验证应具备的最小结构

1. 先固定同一候选时段及三路输入版本，补齐真正纯画面证据。新增推理预算另行确定；旧联合向量不能冒称纯画面。
2. 最小对照可为同一背景变换、候选、拒绝校准下的“max、无加分”与“原提议的 max＋事前固定有限加分”。它检验共识加分是否值得，而不是搜索大量权重。加分规则、标签和预算未预注册前不运行。有足够新标签后才加入保留分差的 CC 或带 max 特征的 L2 学习，不在冻结七题上枚举挑最好成绩。
3. 新查询覆盖纯画面、非语言声音、对白、明确跨模态复合条件、无关及意思相反的负例；目前对白样本不能代表非语言音效检索。
4. 模型选择/权重拟合、拒绝校准、最终验证分开。按查询及源片段/源视频分组，避免重叠窗或同一句改写落入训练与验证两边。仅有三条原片时，报告只能是有限诊断。
5. 分别报告各类 Top3 与正确时间、全库无答案误报，以及各路单独和融合后的失败。所有过往失败保留；不把最终分数显示成命中概率。
