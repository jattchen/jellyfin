# EmbeddingGemma 2 视频片段搜索实施约定

状态：2026-10-14 用户已确认共同理解，方案已固化并回读核对于 [Issue #1](https://github.com/jattchen/jellyfin/issues/1)，进入分支开发与隔离验收。

## 已确认的用户结果

- 在 Jellyfin 网页内输入自然语言，搜索视频画面与对白的含义。
- 本机模型为 `google/embeddinggemma-2`，复用已有独立模型 HTTP 服务。
- 首版启用“动漫”视频库，当前有 3 条视频、合计约 68 分钟；索引覆盖每条视频的完整时间轴。
- 返回影片及约 5–10 秒的命中时间区间。点击后从该区间起点继续播放完整视频。
- 对白按主题及近义表达检索；逐字台词匹配和新增语音转写能力不作为首版要求。
- 已启用库的新增、内容变化与删除自动更新；提供进度、暂停、恢复及失败重试。
- 交付服务端与配套网页的开发分支，只在未修改的官方 12.2 隔离实例验证。本次不发布或替换现有部署。
- 用户补充：改好的 Jellyfin 目标为本机原生运行，不采用 Docker；后续在本项目中由 Agent 执行官方升级。隔离验收同样采用 macOS 本机原生 12.2。
- 用户确认首版采用独立 SQLite；真正不兼容且确需重新分析视频时，保留旧数据，暂停受影响片段搜索，由管理员选择时机启动重建。
- 用户确认固定样本以“前三项找到”为搜索相关性验收门槛；播放定位与完整覆盖另行检查。
- 用户进一步确认首版固定联合音视频向量，每窗一条；使用现有视频接口约每秒一帧的采样，不加入分离向量或密集图片对照。
- 用户确认弱相关候选默认折叠，可展开查看；验收只计默认可见前三项，折叠区不计入通过门槛。
- 用户确认 Jellyfin 报告视频正在播放时暂停派发索引窗口，播放结束自动继续；已完成且仍有效的窗口立即可搜，明确标记视频索引尚未完成。

## 实现边界

1. 服务端采用独立插件模块，提供片段检索、索引状态及管理员控制接口。复用 Jellyfin 当前用户权限、影片身份与播放器。
2. 原搜索页面继续显示标题结果，增设独立加载的“画面与对白片段”区域。需要在 jellyfin-web 建立配套开发分支。
3. 模型服务仅负责生成向量，插件负责分段、索引、排序和有效性。模型不返回命中时间，时间来自已记录的窗口起止位置。
4. 先检验真实片段的相关性，再处理选定库全部内容。6 秒窗口、4 秒步长是首个验证基线；片头到片尾必须没有时间空洞。首版固定联合音视频输入及现有视频抽样，不以未经确认的表示切换或新增语音转写掩盖未通过结果；未达标时保留失败证据，回到访谈调整。
5. 首版使用插件专用 SQLite，同库保存资源、内容版本、窗口、任务、向量与有效批次；查询时精确比较当前有效向量。速度通过实测验收，后续依据规模和测量结果决定是否引入 Qdrant。约 1,020 窗口的一路 768 维 float32 向量约 3 MiB；这是容量估算，不是性能结论。
6. 不接入目前只返回影片 ID 和分数的外部标题搜索提供者，避免片段结果覆盖原标题搜索。
7. 每次后台仅提交一个窗口，插件自己的查询优先，队列忙时退避。Jellyfin 报告正在播放视频时停止派发新窗口，当前推理完成后暂歇，播放结束自动继续。手动暂停保持到管理员恢复；共享模型服务中已在处理的请求仍需等待结束，界面准确显示状态。
8. 不更改 home-search、现有模型服务或其索引；真实素材只读，测试实例禁止向原媒体目录写元数据。

## 验收约定

- 在看搜索排名前冻结 12 条查询及目标：5 条画面、5 条对白、2 条无答案。覆盖不同视频及片头、中段、片尾，含跨窗口与声画不同的场景。
- 画面和对白两组各至少 4/5 的查询，在默认可见的前三个片段结果中包含真实目标；展开弱候选后找到目标仅作为补充证据，不计入通过。无答案例子提示未找到明显相关片段，低相关候选折叠在“可能相关”区域；相似度不作为命中概率或逐字对白证明。此标准只对应首版选定库及冻结样本，不代表所有查询都能正确定位。
- 命中区间应为约 5–10 秒且包含目标内容；另行检查播放器从请求起点播放及连续跨越区间结束，不能只用返回时间值证明真实播放正确。
- 三条视频从开头到片尾全部覆盖；失败窗口明确列出，不能有缺口仍显示完成。
- 搜索、结果详情与播放入口使用当前用户授权；验证撤权、删除、移出启用库及内容替换后的旧结果失效。
- 核对模型、权重版本、处理版本、维度与切窗规则；不兼容索引明确不可用。
- 验证暂停、恢复、重试与进程中断，迟到任务不能激活旧内容或覆盖新批次。
- 插件关闭、模型离线、超时或繁忙时，原标题搜索仍正常；快速更换查询不显示旧查询结果。
- 记录推理吞吐、峰值内存、临时磁盘与后台处理时的查询等待，先按实测估算整库耗时。
- 主 Agent 在最终服务端、网页和插件版本上亲自验证关键用户流程，保存脱敏证据。

## 已确认的片段与调度细节

- 原生 `video` 输入使用 `video_audio: true`，每个窗口产生一条联合向量，结果按统一音视频相似度排序；不从这个向量声称能区分某一帧或某一句对白。
- 模型服务的视频采样约每秒一帧，上限 32 帧；6 秒短窗通常约 6 帧。完整时间轴覆盖不等于逐帧分析，短暂闪过的画面可能没有被采到。
- 当前三个来源在 Jellyfin 元数据中各登记一条默认音轨，未登记字幕轨；语言字段未知。此为元数据核查，不是已听辨音轨或已检查烧录字幕。
- 使用相同切窗记录管理输入、向量与播放起点；尾窗覆盖片尾，输出失败或不完整的窗口明确进入失败状态。
- 窗口成功后可以独立成为可搜索结果；视频状态仍显示索引未完成，只有全部窗口成功才显示完成。首次索引、新增视频或存在失败窗口时，不能依据局部无结果推断整条视频没有目标内容。
- 播放造成的自动暂歇、管理员手动暂停、模型不兼容及失败重试分别记录原因；播放结束不能解除手动暂停或模型不兼容。
- 暂停停止派发新窗口，当前合法任务可完成并持久化；内容被删除、替换、任务取消或代次失效后的迟到输出不得上线。
- 原生视频抽样、联合音视频输入和弱结果阈值都属于明确记录的处理配置；阈值经真实样本校准，最终验收按预先冻结的查询、目标及通过条件执行。

## 环境与交付

- 服务端分支：`feat/embeddinggemma2-video-search`，基于已更新的 `origin/master`。
- 当前部署仍为 Jellyfin 10.11.11。用户已选择首版仅支持官方最新正式版 12.2；其 server/web 固定为配对发行版，插件基于官方 12.2.0 NuGet 开发包构建。现有分支的 master 源码已是 13.0.0，仅作为仓库容器，不作为插件项目引用或正式支持目标。
- 隔离实例使用独立用户、配置、数据库、缓存、端口与插件索引目录。来源凭据、影片身份、标题、路径、字幕、原始媒体和向量不提交 Git。
- 按用户先固化 Issue 的要求，已在 `origin` 对应的 `jattchen/jellyfin` fork 启用 Issues；[Issue #1](https://github.com/jattchen/jellyfin/issues/1) 是方案、实施与验收入口。
- 交付包含分支路径、构建与检查结果、真实搜索及定位证据、使用说明和实际尚未通过的项目。

## 源码侵入预算与模块边界

- 服务端核心源码、根 `.sln`、根中央包配置和 Jellyfin 核心数据库：零修改。
- 新增独立插件项目及其测试、构建、依赖配置；使用官方 NuGet 包，不引用本仓库服务端源码项目。插件目录拥有独立 MSBuild 配置及 SDK 选择，防止继承父仓库设置。
- 网页以官方 12.2 为基线，目标仅在 `src/apps/legacy/routes/search.tsx` 挂接新组件；片段请求、结果展示及播放器调用均放入新增模块。原标题搜索取数与播放器内部逻辑保持原路径。最终实际文件差异由主 Agent 审核。
- 不采用 DOM 注入、读取私有浏览器存储或在运行中改写官方静态文件的接入方式；配套网页按已审核源码构建。
- Jellyfin 适配层只负责当前用户权限、媒体身份与查询、变化事件、任务生命周期及稳定数据目录。切窗、模型 HTTP 协议、索引状态与排序使用插件自己的数据类型。
- 网页单独封装认证请求和原生播放调用，未来官方网页改动时只调整这个接入层与挂接点。

## 对外接口约定

- 插件接口使用自有的版本前缀，例如 `/EmbeddingVideoSearch/v1/`，不修改官方搜索响应或生成式 SDK。
- `capabilities` 返回接口版本、已验证宿主版本及可用性，不把未验证版本报告为兼容。
- `search` 接收查询文字、当前界面的库过滤及数量上限；服务器从当前登录身份获取用户，不接受调用者指定任意用户身份。
- 每个结果包含影片身份、媒体源身份、窗口身份、起止 ticks 及命中表示类型；不把向量或本机媒体路径返回给网页。1 秒为 10,000,000 ticks。
- 结果时间来自切窗记录，不声称是模型自行预测的具体发生秒数。通过窗口真实内容及实际播放器定位分别验收。
- 管理员控制接口提供索引状态、暂停、恢复、重试与重建；普通用户只访问其当前获准影片的片段结果。
- 网页处理接口缺席、版本不匹配、模型繁忙及失败状态；旧查询的迟到响应不会盖过新查询。

## 索引与生命周期约定

- 稳定索引目录位于宿主 `DataPath` 下按插件固定 ID 划分的专属目录，不放在会被插件卸载删除的 DLL 安装目录。
- 任务、向量、时间窗及有效批次使用同一 SQLite 事务边界。任务持有内容版本与运行代次；删除、替换、取消或代次失效后的旧任务不能激活结果。暂停只停止继续派发，合法的当前窗口完成后可以保存。
- 媒体事件仅记队列，避免在 Jellyfin 媒体回调中执行切片或模型推理。定期完整核对用来弥补停机遗漏；来源失败保留未知状态，不批量认定删除。
- 标题变化只更新展示信息；视频内容变化使旧时间窗失效并安排重建。每条视频覆盖完整时间轴后才标为完成，整个库的进度分别列出完成、等待与失败。
- 记录内容、模型、权重 revision、processing_id、维度、切窗及音轨规则，识别特征空间、输入表示与时间窗的变化；签名变化先检查影响，不将每次软件升级直接等同于全库重算。官方服务端升级本身不要求重算同一批兼容向量。
- 确认模型或处理变化不兼容时，保留旧数据，暂停受影响片段搜索并提示管理员，由管理员启动所需转换或重建；禁止将不兼容旧向量混入新模型查询。仅处理受影响的范围；支持可靠转换或窗口复用时避免重复推理。
- 暂停持久化并阻止继续派发；已经开始的原生推理可能需要等待结束。关闭、升级和卸载解绑媒体事件并排空或取消工作，保留独立索引数据。
- 插件自己的 schema 迁移前生成一致性备份；遇到无法理解的更新 schema，旧插件拒绝写入。

## 官方升级检查约定

1. 记录已验证的官方版本、源码提交、插件开发包、网页补丁及模型签名，首版范围为 12.2。
2. 新版升级前，在独立环境构建插件并检查网页挂接补丁能否应用，直接暴露接口或文件路径变化。
3. 在未修改的官方服务端验证插件加载、认证与权限、媒体变更、旧索引读取及后台暂停恢复。
4. 在配对网页验证原标题搜索、片段搜索、原生从命中点连续播放；构建通过不代替这些场景。
5. 根据结果更新明确的支持版本记录。插件清单的最低 targetAbi 不作为未来所有版本兼容的证明。

## 本机原生运行与后续 Agent 入口

- 测试与未来目标均为 macOS 原生运行；本机模型服务使用 loopback 地址。当前 Docker 10.11.11 仅作为只读素材来源及现状参考，不作为首版运行平台或兼容验收目标。
- 原生隔离实例使用自己的配置、数据、缓存、日志及端口。模型已有独立进程，插件通过 HTTP 复用，不重复加载权重。
- 原生服务端使用固定官方 12.2 代码或发行产物，匹配官方网页版本及插件开发包；确认实际运行版本、架构、FFmpeg 与插件加载结果。
- 在本项目保留升级说明、已验证版本记录及可复现的构建/检查入口，供后续 Agent 接续；检查必须保留项目内未提交内容，不覆盖用户改动。
- 后续 Agent 先核实当前运行版本、插件与网页补丁、数据目录及索引签名，在独立环境验证新官方版本，再依据当次任务授权执行正式升级。
- 官方宿主或网页升级的适配工作集中在插件宿主适配层、网页挂接点和播放/认证适配层；模型及切窗协议兼容时复用已有索引。
